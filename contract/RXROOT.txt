- Rx chain: AGC -> RRC(sfix16_En12 out) -> [SymbolSync(Gardner) -> CoarseFreqComp(CFC est+

  PhaseAmbiguity -> PacketController] -> QPSK_Demod -> FEC(deint+Viterbi+descr+BIST).
  NOTE: CFC sits AFTER symbol sync (symbol-rate estimator).
- AXI map (word addr<<2): 0x10C iq_debug_mux, 0x110 rstCS, 0x114 rx_input_select,

== FINDING F1 (INSTRUMENTATION, both kits): rstcs register is MISWIRED ==
Frequency_and_Time_Synchronizer.v: `assign rstcsDet = Coarse_Frequency_Compensator_validOut;`
i.e. the 0x150 rstcs counter counts the CFC VALID strobe (= symbol strobes, 240 k/s),

(under-read due to AXI sampling). Present in BOTH kits (zed line 169, jupiter line 185).
Fix later in taps overlay; does not affect datapath.

== ROOT CAUSE (datapath) ==
Coarse_Frequency_Compensator: feedforward z^4-autocorr estimator (Integrator window
4096 symbols, Reset_Generator count-to-4096; Extract_Frequency angle/2; /4 gain) jumps
the CFC NCO frequency every 4096 syms (58/s). At real-air SNR the 4th-power-law angle
noise gives sigma ~150-300 Hz per estimate (theory ~150 Hz @14 dB; measured 270 Hz).
The carrier sync must re-acquire after every jump and never converges -> permanently
rotating constellation -> preamble (differential Barker) still fires but payload ~50% BER.
IN NOISELESS BIST LOOPBACK the z^4 estimator noise is ~0 -> failure is sim-invisible
with synthetic stimulus; exactly matches "BIST passes, air fails" history on BOTH boards.
On-chip evidence re-read: zed cfc_est -184+-88 Hz (= estimator noise, true offset
unknown but small), jupiter +-30 kHz swings (same disease, worse conditions).

== E14 (v6): two silicon defects root-caused ==
ZED v5 SILICON: BIST DECODED ON CHIP -- CAP_OUT 0x04922282 GOLDEN, BER 0.025%,
rstcs=0, cfc ~ -0.5 Hz. v5 Rx datapath CORRECT on zed.

DEFECT 1 (zed spontaneous reset ~1/min):
BD trace: TxRxCompo_ip_0/IPCORE_RESETN (and AXI4_Lite_ARESETN -- same net)
= rx_rstn_inverter/Res = NOT(axi_adrv9001/adc_1_rst). adc_1_rst is the ADI rx
core reset, re-asserted on SSI resync events; ADRV9001 runtime tracking
calibrations (~1/min cadence) interrupt the SSI -> adc_1_rst pulse -> modem
full reset. RTL check: the BIST counters (FecCounters.v) clear ONLY on the
async top reset -- no self-clear paths (frame-sync-loss etc.) exist. So the
mid-run zeroing (673->24 with continuous uptime) is exactly reset pulses.
Timing marginality RULED OUT as the resetter: clean periodic zeroing is a
reset signature (timing corruption would raise BER, not zero counters), and
the 0.025% BER between pulses shows the +0.006 STA closure holds on silicon.
FIX: STICKY RESET in the IP top (TxRxCompo_ip.v): reset_cm =
(~IPCORE_RESETN) & ~rstDone, rstDone latched at first release. AXI soft reset
(reset_internal) unchanged -> host keeps a deliberate reset. Also protects
the AXI regfile (skip/input-select) from reverting to defaults mid-run.

DEFECT 2 (jupiter Rx ~46%):
Clock picture reconciled: axi_adrv9001 s_axi_aclk = sys_cpu_clk = clk_pl_0 =
100 MHz (BD-verified), so CLK_FREQ 0x9D4 = 2516/65536 x 100M = 3.84 MHz =
adc_1_clk = IPCORE_CLK, CLK_RATIO 4 -> dclk 15.36 MHz (LVDS DDR at 1.92 Msps).
The 3.84 MHz IPCORE is DESIGN-CORRECT for Tx: REP_TxI/Q are x2 POLYPHASE
INTERPOLATORS clocked on enb_1_2_0 (mod-2 phase counter selecting coefficient
banks), so Tx out = clk/2 = 1.92 Msps -> the measured 240-ksym air is exactly
right. The Rx breaks because its ingress DECIMATES: Downsample2/3 pass input
through only on enb_1_4_1 beats; with the /2 rail equal to the stream rate
(1 ingress beat per TRUE sample) this discards every other sample -> QPSK Rx
ran at 4 sps against the SS8-tuned design -> ~46% BER. (v5's N=2 on the /4
rail made it 2 sps -- consistent with 'slightly worse than v3'.)
TRUE jupiter rail:sample ratio: enb_1_2_0 = 1.92 MHz = EXACTLY 1 beat/sample
(N=1 on the /2 rail; the /4 rail is 0.5 beats/sample and can never work).
FIX (RX_DIV2_RETIME): Downsample2/3 passthrough retimed enb_1_4_1->enb_1_2_1
(no decimation), Delay3/Delay ingress regs enb_1_4_0->enb_1_2_0, and
