# Cyclic RX DMA fix — patch bundle

Fixes the ~2% RX byte-link PER (~1 lost frame per DMA transfer boundary). Root
cause: `axi_adrv9001_rx1_dma` is synthesized `CONFIG.CYCLIC 0`, so the single
S2MM engine must be reset+resubmitted by the host after every K-packet transfer;
a late resubmit misses the next frame's `SYNC_TRANSFER_START` tuser. Fix: build
the RX1 DMA `CONFIG.CYCLIC 1` so the engine auto-restarts in hardware (the
per-boundary re-arm shrinks from a host round-trip to a few clock cycles), and
switch the host to a ring reader.

## Files in this bundle
- `system_bd.tcl.patch` — the exact one-line HDL change (rx1 `CYCLIC 0`→`1`),
  verified against the file (only line 325 changes). rx2 left as-is (unused).
- `HOST_RING_REWRITE.md` — the host-side change for `host_app_k5/qpsk_tun.c`,
  grounded in the axi_dmac IP source with file:line anchors.
- `README.md` — this file.

## What to change (two coordinated changes)
1. **HDL:** apply `system_bd.tcl.patch` → RX1 DMA is built `CYCLIC 1`. This is
   *permissive*: the flag only engages when the host also sets FLAGS bit0
   (`up_dma_cyclic <= up_wdata[0] & DMA_CYCLIC`, regmap_request.v:188), so the
   new bitstream still runs the current host binary unchanged.
2. **Host:** add the env-gated cyclic ring path (`QPSK_RX_CYCLIC=1`) per
   HOST_RING_REWRITE.md. Default stays the legacy non-cyclic path.

Deploy the bitstream first, confirm the legacy host still links, then flip the
host env var. Rollback at each stage is a restart, not a reflash.

## Build + deploy steps (reference only — DO NOT run here)
The DMA config file lives in the **generated** HDL project
(`.../vivado_ip_prj/projects/jupiter_sdr/system_bd.tcl`), which is *excluded*
from the kit rsync (`build_byte_image.sh`: `--exclude 'hdl_prj_*'`) and
regenerated by the MATLAB reference-design step. So editing the in-tree copy
alone is overwritten by a from-scratch build. Apply the patch to the ADI HDL
source that seeds `system_bd.tcl`, **or** inject it after the MATLAB step
populates `hdl_prj_jupiter_composite` and before Vivado synthesis.

Build flow (as the shipped lean image was produced —
`jupiter_byte_lean_build/build_lean_image.sh`):
1. `jupiter_240k5_byte/run_full_gates_t8.sh` — HDL gates (must be green).
2. `build_byte_image.sh <FRESH>` — MATLAB `build_variant_byte` generates the
   byte reference-design IP + BD; **apply the CYCLIC patch to the generated
   `system_bd.tcl` here**; then `complete_byte_t8.tcl` runs synth/impl/bootgen
   → `<FRESH>/hdl_prj_jupiter_composite/vivado_ip_prj/boot/BOOT.BIN`.
   (The lean image also runs the dual-DMA tap BD step; keep or drop per intent.)
3. Rebuild the host: `make -C host_app_k5` (adds `QPSK_RX_CYCLIC` path).
4. Deploy per `two_jup/deploy_image.sh <board-ip> <BOOT.BIN>` (staged, one board
   at a time; backs up `/boot/BOOT.BIN` — Jupiter has no remote power, a bad
   `/boot` is a physical reflash). Ship the new host binary alongside.

## Estimated risk
- **HDL change:** low. One IP parameter; the TX DMAs already run `CYCLIC 1`, so
  the cyclic path is exercised silicon. Bitstream is backward-compatible with the
  current host (permissive flag).
- **Host change:** moderate, but env-gated and reversible. The real hazards are
  named in HOST_RING_REWRITE.md §2(d): a leftover `rx_done()` gate silently
  stalls RX (TRANSFER_DONE never sets in cyclic mode), and a host that falls a
  full ring-lap behind silently overwrites unconsumed frames — both are made
  detectable via the seq-cursor design.
- **Honest caveat:** the source does not prove the loss goes to exactly zero. A
  residual single-cycle re-sync race at each lap boundary is not excluded by
  reading the RTL. Expect the loss to drop by orders of magnitude.

## Validation plan
Re-run the existing gap-based delivered-PER measurement and confirm the periodic
miss-train collapses:
1. Capture per-frame telemetry with `QPSK_FRAMELOG` on both the current image and
   the cyclic image over an identical load (same `two_jup` capture harness, e.g.
   `capture_paired.sh` / the R3 goodput probe).
2. Run `two_jup/frame_taxonomy.py <frames.bin>`: it computes the delivered PER
   from `host_seq` gaps and the **autocorrelation of the per-frame error train**
   (frame_taxonomy.py:124-152) plus the host-missed-frame count
   (frame_taxonomy.py:214+).
3. **Pass criteria:**
   - delivered PER (host_seq gap rate) drops from ~2% toward <1% (campaign goal);
   - the lag-M peak in the error-train autocorrelation — where **M = `rx_multi`**
     (the K-packet transfer stride that currently sets the miss period) — drops
     to noise (`period_strength` no longer credible);
   - `host-missed frames` count falls sharply.
4. Watch the new overrun counter (seq jump ≥ RING_SLOTS, folded into
   `st.seq_gaps` / framelog) stays zero under sustained load; if not, grow
   `RING_SLOTS`.
